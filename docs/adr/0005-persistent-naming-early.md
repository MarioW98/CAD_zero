# ADR-0005: Persistent naming by genealogy + subshape tracing

## Status
Accepted (2025-10-07) — **CORRECTED** from the original proposal.

## Context
The original proposal suggested persistent naming based on
"firma geometrica + genealogia". This is fragile:

- **Fillet/chamfer** change vertex positions and create new faces; the
  geometric signature is destroyed.
- **Parameter edits** move every coordinate downstream; signature
  matching would have to be approximate, and approximate matching
  is exactly what causes the bugs we are trying to avoid.
- **Boolean operations** re-shape topology wholesale.

Topological naming based on geometric signature is the well-known
"wrong turn" that OpenCascade's OCAF took for years before introducing
history-based naming (Andrade 1998, Chen & Luo 2010).

## Decision

### `ShapeId` composition

```cpp
struct ShapeId {
    FeatureId    feature;     // stable across rebuilds
    SubshapeRef  subshape;    // path of indices (max depth 8)
    Generation   generation;  // rebuild counter
};
```

- **`FeatureId`** is generated by the feature that *creates* the shape.
  It is stable across rebuilds; it is only invalidated when the user
  deletes the feature explicitly.
- **`SubshapeRef`** is a path of 32-bit indices that traces from the
  feature's root output down to the specific subshape (vertex / edge /
  face of a B-Rep, or leaf node of an SDF tree). Each index encodes
  "the i-th output of operation j at this depth".
- **`Generation`** is the feature-tree rebuild counter. A reference
  is stale if `id.generation < current_generation`.

### Subshape tracing, not signature matching
When a feature rebuilds, the new subshapes are matched to the old
subshapes by *tracing the operation that produced them*. For a boolean
union `A ∪ B`:
- Each output face is traced to its origin in `A` or `B` (or marked
  as a "split face" if it came from a face that was split by the
  intersection curve).
- The output face's `SubshapeRef` is built by appending the boolean
  op's index and the local face index to the originating subshape's
  ref.

### Generation-based invalidation
If a user deletes a feature, the feature's id is invalidated. Any
downstream reference whose path starts at that feature is reported
as "dangling" by the rebuild system, which surfaces a user-visible
error rather than silently picking a wrong face.

## Consequences
- Phase A ships the `ShapeId` ABI.
- Phase A includes a minimal test: rebuild a sphere → box union
  after editing the sphere's radius; the boolean op's output ID
  is stable.
- Phase F (modeling parametrico) is where the real stress tests land.
- No geometric signature is ever used for naming.
