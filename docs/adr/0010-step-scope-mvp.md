# ADR-0010: STEP MVP scope — AP203 edition 2 only

## Status
Accepted (2025-10-07)

## Context
STEP AP242 is the modern edition, but its scope (3D model-based
product definition with GD&T, tessellated geometry, kinematics, …)
makes a from-scratch parser/writer a multi-year effort. OpenCascade
has thousands of files dedicated to STEP. We need a realistic MVP.

## Decision
**MVP STEP scope**: AP203 edition 2, with `advanced_brep_shape_representation`
restricted to analytic surfaces (plane, cylinder, cone, sphere, torus).

### In-scope entities (Phase D)
- `PRODUCT_DEFINITION`, `PRODUCT_DEFINITION_FORMATION`
- `SHAPE_REPRESENTATION` with analytic-only geometry
- `MANIFOLD_SOLID_BREP`
- `ADVANCED_FACE` with `PLANE`, `CYLINDRICAL_SURFACE`, `CONICAL_SURFACE`,
  `SPHERICAL_SURFACE`, `TOROIDAL_SURFACE`
- `EDGE_CURVE` with `LINE`, `CIRCLE`, `ELLIPSE` (the latter only if
  generated by analytic intersections)

### Out-of-scope (post-MVP)
- `B_SPLINE_SURFACE_WITH_KNOTS` / `B_SPLINE_CURVE_WITH_KNOTS` (general NURBS)
- `TESSELLATED_*` entities (tessellated B-Rep)
- `GEOMETRIC_TOLERANCE` and GD&T
- Kinematics, assembly structure, PMI

### Round-trip test policy
- Tests use STEP files *generated by CAD_0 itself*.
- We do **not** promise to import STEP files generated by SolidWorks,
  NX, or CATIA in Phase D. Interoperability with external CAD systems
  is a Phase H goal.

## Consequences
- The Phase D STEP reader can be implemented in ~3000 lines of C++
  rather than the ~30000 a full AP242 reader would require.
- Users importing STEP from external CAD systems will see a clear error
  message listing the unsupported entities encountered.
- Phase H will lift the analytic-only restriction by adding NURBS support.
