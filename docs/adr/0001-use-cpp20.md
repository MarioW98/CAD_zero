# ADR-0001: Use C++20 for the core kernel

## Status
Accepted (2025-10-07)

## Context
The core kernel (`core/`) needs a systems language that is:
- Performance-predictable for tight inner loops (SDF evaluation, predicate checks)
- ABI-stable so Python bindings can be shipped as binary wheels
- Cross-platform (Linux + Windows at minimum)
- Mature in its toolchain (CMake, sanitizers, profilers)

## Decision
We use **C++20**, restricted to the subset that is well-supported by
GCC ≥ 11, Clang ≥ 14, and MSVC ≥ 17.10.

### Supported features
- Concepts
- `std::span`
- `std::ranges` (caveat: MSVC support is partial)
- `std::format` (caveat: MSVC ≤ 17.9 does not ship it; we use `fmt` as a fallback)
- Designated initializers
- `consteval` / `constinit`
- Three-way comparison (`<=>`)

### Forbidden features
- C++20 modules — too brittle across the three compilers, mixed CI history
- Coroutines — fine to use internally but not exposed through the public API
- `std::execution` (P2300) — not yet shipped; we use TBB instead (see ADR-0009)

## Consequences
- All public headers compile with `-std=c++20` and no extensions.
- MSVC requires `/permissive-` and `/Zc:__cplusplus`.
- FP contraction is disabled (`-ffp-contract=off` on GCC/Clang, `/fp:strict` on MSVC) for cross-platform determinism (see ADR-0014).
